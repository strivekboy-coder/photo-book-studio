# Photo Book Studio：完整使用流程

这是制作照片相册与可选 Plog／电子手账的 Codex skill。普通相册仍是默认路线；不是上传旅行照片就自动启用手账。用户明确要求 Plog、手账或提供这种风格参考时才启用。主题、视觉风格与成品用途分别记录：印刷相册里的手账风仍遵守相册与印刷流程。

## 入口：只在用途不明确时问“相册还是 Plog／手账？”

已明确说要做哪一种就直接分流，不重复问。选择 Plog 后，不需要回答后面的相册问卷。

## 普通相册：先回答相册问卷

新相册在导入、编排、生成之前，先使用 [完整固定问卷](intake-questionnaire.md)。用户已经回答的题不重复问，创意处理的许可分别询问。问卷共15题及可跳过的6b：故事与对象、成品、版型、选图、上传方式、页面节奏、预算/页数、视觉风格、文案来源、文字语气与语言、基础修图、贴纸、封面、撕纸、艺术衍生、照片简化。回答可简写，也可接受推荐项。

1. **问卷优先。** 未明确的重要事项再补问；已有答案不重复问，后续批次不重跑首次问卷。
2. **保存答案。** 将明确回答、接受的推荐、推断与未知项区分记录到 `project/brief.json`，再开始导入和制作。
3. **建立照片清单、读照片。** 记录原文件身份、尺寸、方向、分辨率、拍摄时间和校验值。看所有新图的联系表，对人物边缘、重要画面和疑难裁切看大图。原图只读。
4. **按事件与故事分组、规划篇幅。** 时间线确定叙事顺序，同一天可以为画面流动调整。事件不机械等于一天或一跨页。每张选图默认出现一次，不能因为相似或难排而舍弃。
5. **决定视觉方向。** 选择、修改或新建版式。编辑式、诗意图文、拼贴和 zine 是参考结构，不能限制新参考；疏密、大图、小片段和安静停顿共同形成节奏。根据实际文案比较字体，检查缺字与可读性。
6. **写真实文案。** 保留用户提供的事实、名字、玩笑和情绪；没有文案时，只写少量可见事实草稿，不编造日期、关系或经历。
7. **完成普通图文编排。** 照片裁切、大小、对齐、色彩与文案共同构图。纸条、票根、口袋、背景、涂鸦与贴纸在有实际作用时加入，不挡脸、手或重要内容。风格与密度由用户与照片决定。
8. **落实与复核创意候选。** 候选筛选在读图与视觉方向阶段进行，不能等排版完成才首次考虑。 Minimal Zine Poster、Photo Abstract Editorial、Gathered Scenes、Photo to Zine Postcard、Travel Envelope、主体突破画框、三照片纸感拼贴。读图后、构图定稿前逐项评估，允许全部跳过；先比较合适且许可允许的候选，再决定分组与布局，成图后复核效果。后三条的说明与两个用户 prompt 随 skill 提供。
9. **实际渲染并修正。** 看浏览器导出的画面，检查裁切、文字、材料边缘、前后遮挡与连续页面节奏。核对每个照片身份及出现次数，证明没有遗漏。仅有数据检查通过不能算审美通过。
10. **内页完成后再做封面。** 按整本内容制作获准的插画封面，或遵循用户的照片/文字封面选择。没有生成工具时保留可行方案。单张 Plog 不要求封面。
11. **按要求交付。** 网页、图片或明确要求的 PDF；印刷需另外检查尺寸、出血、分辨率和打印方要求。只讨论 PDF 不代表要求生成。
12. **按比例继续修改。** 沿用保存的偏好与读图结果，后续批次只分析新照片，局部修改只检查相关页面，结构调整后重新核对当前页码与照片身份。

## Plog／电子手账：图像生成主导的短流程

明确说要做Plog后，不填相册问卷；可提供风格、参考、文字、贴纸，没有偏好就根据照片设计。默认3:4、选图各一次、原图只读、短文案与分享图片；默认浏览器预览仍带编辑器，明确只要图片则不交付网页。未知日期、地点和关系不猜；PDF和公开发布须明确要求。

1. **确认已有信息，读图分组。** 保存偏好、源文件身份/时间/尺寸/校验值，查看全部新图，重点图看大图。按照片关系和辨识度决定页数，不套印刷相册的展开节奏。
2. **提前规划视觉关系。** 例如照片与注记互穿、场景直接作底、动作跨框、大小快照交错；先确定作用，不先手工精修所有纸边、掩膜和涂鸦。 照片、文字、材料和情绪重点一起构思。使用用户参考、已有案例或原图；只有缺少明确方向/材料/准确文字方案时才搜索网站、找素材、比较本地字体。七路线快速适配，记录所选候选和重要限制，不强制写七份不用的理由。
3. **轻量排版，按需插入创意组件。** 普通Plog＋最后整页imagegen加工为默认；信封、叠纸只在有具体收纳/主次作用或用户指定时使用，并查看本项目近期作品避免重复。 创意处理、页内组合与最终增强可以串联，不是互斥分支。例如：原图＋创意prompt／子skill→完整作品或组件→整页排版→imagegen手绘增强；完整作品也可直接增强，已经有效就停止。 完整创意作品/组件直接将实际原图和完整prompt交给imagegen；普通Plog先做轻量基础排版，再把完成页与必要原图交给imagegen整合手写、虚线、箭头与装饰。基础已经有效时不强制增强。原像素必须不变或工具无法保真时，才用真实照片图层与独立装饰的备选。
4. **最后让imagegen实现关系，再做一次成品检查。** 完成页与必要原图一起输入，让动作跨边、标记、手绘虚线、图案和材料关系整合生成；若一次生成已完成整页表达，不重复加工。只检查最终全页和手机预览的漏图/重复、明显错脸错肢体、重要错字或遮挡，以及表达效果。删除逐像素变化核对和每轮放大对比原照；普通细节重构或认可前景不作为失败。明显问题才回看原图诊断并集中修正。
5. **交付并按需修改。** PNG/JPG为主；网页编辑时原生照片文字可单独调，生成的信封/叠纸群整组调，扁平增强图作为分享成品。浏览器草稿不自动改变导出的图片。无需默认PDF。

信封原方法含风景背景，适合直接保留完成图的背景与前景，再在安全位置放其余照片，不自动抠掉背景。内容可有真实主体抠图和物件体积，薄信封不等于里面全是方相片。局部叠纸第一次就请求外部透明、内部白纸保留，其他原prompt要求不动；可加入一枚小型植物/花朵作从属点缀。三图或四图适配必须同步prompt、附图和来源记录。

详见 [Plog短流程](plog-workflow.md)、[生成提示词与原始prompt](creative-prompts.md)、[工具格式](plog-schema.md)。记录真实生成输入、prompt、输出与审稿结果。图像工具必须实际可用，其他创意子skill为可选增强。不能保证所有模型都有相同审美。

## 七条路线怎样选

| 路线 | 常见作用 |
|---|---|
| 极简 Zine | 封面、章节停顿、少量文字与单一重点 |
| 照片抽象记忆 | 原照与从照片提取的抽象记忆面板 |
| Gathered Scenes | 真实照片通过纤维撕纸边与插画相接 |
| 旅行明信片 | 小插页、票卡或独立纪念卡 |
| 信封旅行拼贴 | 景色作底、薄纸信封托起不同照片与主体 |
| 主体突破画框 | 矩形里保留原景，主体轮廓跨入白色留白 |
| 三照片纸感拼贴 | 主图与一横一竖辅图、薄纸层叠和大面积米白留白 |

普通相册仍评估七条；Plog将它们作为快速适配菜单，不强制七条逐项长文。七条都不是使用配额。普通批次以少量强候选为起点，用户明确要求整页风格时可按需要安排。生成衍生图可能改变细节；若必须保持原像素，采用真实照片图层和蒙版。新增艺术处理不自动授权替换原照，不制造原图没有的身体、枝条、人物或旅行事实。

## 下载后可以依赖什么

完整 skill 文件夹包括规则、参考、七路线政策、两个原始 prompt、独立信封适配 prompt、相册与 Plog 的初始化/清单/构建/导出工具、编辑器，以及许可随附的基础字体和少量原生 SVG。所用较大字体/材料按项目获取和缓存。初始化的新项目也有七路线政策，不依赖作者私人目录或这段聊天。

构图、读图、写作和审美仍由使用 skill 的模型执行；脚本提供身份/字体/路径检查与渲染，不会自动挑选优秀构图。没有必装第三方创意插件；生成处理需要当前环境可用的图像工具，其他 creative skills 是可选增强。不同模型和不同照片的审美结果仍需实际审稿，不能承诺固定质量。

作者提示最多在前三次有效使用出现，支持停用，无成品水印或遥测。原照片不覆盖，个人资料不随 skill 分发，发布作品需有授权。完整规则见 `SKILL.md`；具体创意选择见 `zine-policy.md`，新增 prompt 见 `creative-prompts.md`。

新Plog交付前填写v2的 project/plog-review.json，并运行 plog.py check：检查来源与分组、制作路径、实际生成记录及当前版本每页的原尺寸/手机审稿记录。资料研究、字体比较与路线长文不再强制。脚本能发现漏项和过期记录，不能替代审美判断。
