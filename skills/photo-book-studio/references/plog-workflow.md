# Plog: relationships first, imagegen finishing last

Use for explicitly requested standalone Plog/手账. Ordinary albums keep their intake/book workflow. Default ordinary Plog production is: read sources → plan relationships → light basic composition → imagegen implementation/finishing → one final acceptance pass and delivery. Special creative methods may be inserted where useful; they are not the default page template.

## 1. Brief and original sources

Skip the album questionnaire for a clear Plog request. Invite optional style/reference/copy/stickers only when helpful; delegated judgment is sufficient. Save known facts/preferences and unknowns before production. Default 3:4 sharing images, every selected source once, read-only originals and short honest copy; PDF/publication remain opt-in. Explicit image-only means no editor delivery.

Inventory source IDs, dimensions, orientation, EXIF and archive hashes once. View all new photos in one contact sheet, opening only important/ambiguous crop or gesture details as needed. Later revisions reuse saved analysis. Archive hashes protect source files; they are not comparisons between generated and original pixels.

## 2. Plan one useful relationship before rendering

Choose groups/page count from the story, density and legibility. Plan focal/support roles, important text and what connects them: notes crossing safe photo edges, source scenery as the page field, a gesture crossing a window, or mixed snapshot scales with writing flowing between them. These are concepts for the final image tool to realize; do not manually perfect every mask, doodle or paper edge first. A calm or dense design can both work.

Use originals, supplied references or relevant bundled cases for direction. Browse sites, acquire material or compare native fonts only for an actual unresolved need. The seven treatments are an optional menu before design; record selected ideas and meaningful constraints, not seven essays.

## 3. Make a light base; add a special component only when it helps

Basic Plog + whole-page finishing is the normal path. Keep source coverage, photo hierarchy, intended relationship and draft copy clear. The base is not required to be an already polished native scrapbook.

Envelope, 10–15-layer photo-paper cluster and other source-derived methods remain available. Select them for a concrete collection/focal/grouping benefit or a user request, not simply because they looked good previously. Retain natural-contour food/people/objects and photographic volume where suitable; difficult source scenes may remain framed. Send actual original images and the filled complete prompt into the creative skill/image tool together. Do not generate empty materials and reassemble the inner photographs yourself.

A complete creative artwork can become the base, or a transparent complete component can occupy one part of a larger page beside other photos. An envelope's scenic source may remain the whole page background, with additional content in safe regions; no routine extraction is needed. A local paper component requests external transparency from its first generation while retaining internal ivory paper, source hierarchy and original prompt constraints. Optional accent: 可以加入一枚小型植物或花朵兼职作为点缀，但不要抢夺照片主体。 Change a delegated three/four-photo count in both the prompt and attached images, and label adaptations honestly.

## 4. Let imagegen realize the planned page relationships

After the base/group composition is ready, pass the complete page and the necessary original image references to imagegen. Distinguish editing target from source/fidelity references so photos are not added twice. Ask it to realize the planned hand/leaf/frame crossings, source-responsive arrows, dashed contours, handwriting, small drawn motifs, foreground contacts and material depth. Photo coverage, recognizable people/gestures, important objects and exact requested text remain constraints; original pixel identity is not promised.

Keep the successful internal structure of a generated component intact. Match doodles to actual gestures/material edges rather than decorating every border or uniformly scattering icons. Do not create unnecessary crop assets or native masks when the final image tool can achieve the intended visual relationship.

Stages are composable: original images + creative skill/prompt → integrated artwork/component → optional placement with remaining sources → complete-page implementation/finishing. If a single integrated generation already realizes the complete page and intended handwriting, it has fulfilled this final visual stage; do not add another generation merely to tick a box. Skip generation only for explicit no-generation/exact-pixel preferences, unavailable tools, or a version already approved by the user. Use an honest native fallback where required.

## 5. One final acceptance pass, focused correction and delivery

Inspect the final page at normal full-page and phone viewing sizes. Check source coverage, accidental duplication, obvious unintended face/limb/animal mistakes, wrong/missing important words and key content obscured by decoration. Also check the visible relationship, handwriting/material character, scale/color emphasis and page rhythm against the brief. Readable intact cards alone do not certify handmade expression; more symbols do not certify a better finish.

Do not compare output pixels with source pixels, magnify each face/texture after every generation, compute output/source difference scores or repair ordinary generated smoothing, recoloring or accepted foreground accents to chase pixel identity. No before/after pixel-variation report is required. Reopen an original or critical text detail only when a visible final problem needs diagnosis or the user explicitly requests exact preservation. Original source files remain read-only.

If a visible final problem matters, fix the most consequential issue once and review only the changed page/region. Otherwise keep the successful version and stop. Do not rerender, re-inspect and rewrite notes for every intermediate asset. Store actual inputs/prompts/outputs automatically when possible; intermediate generation inspections are optional, final-page findings remain required. Bookkeeping does not prove image fidelity or aesthetic quality.

Deliver PNG/JPG, with explicit variants named. Retain native base layers if an editable preview is delivered; generated modules move/scale/rotate as groups and flattened final lettering is not separately editable. Explicit image-only output omits editor/HTML/PDF delivery. Use normal source-map/count checks and current final review, preserving intermediate working versions without counting them as extra main-set photo occurrences.

## Avoid repeated templates across a series

Within the current project or a user-authorized recurring series, consult previous pages/briefs for the structural treatment, photo/title anchors, frame construction, material family, palette and handwriting rhythm. Keep style history concise and project-local; do not collect unrelated user history or make fresh users depend on this author's private conversations.

If recent pages repeatedly use a large envelope or layered-paper cluster, prefer an ordinary source/notes composition with a different relationship unless another structural treatment adds a specific benefit or the user wants a unified series. “First consider routes 5–7” means they remain easy to discover when useful, not that every matching group must generate one. No percentage, per-page effect quota or fixed alternation is imposed. Cohesion can come from shared ink/lettering while scale, anchors and texture vary; changing colors alone is not sufficient variety.

## Keep execution proportional

Read the active entry/short workflow once and only the chosen treatment reference as needed. Reuse installed dependencies and the bundled build/render/export tools; do not inspect implementation code or write a new export/packaging script for each routine batch. Independent page generations may run concurrently once their shared direction is decided; dependent finishing waits for its base. Perform one grouped final review, with rerenders only for real corrections. Different generation latency and user requirements prevent a fixed completion-time promise.
